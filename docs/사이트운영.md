# PAINS 콘텐츠 운영 가이드

목표는 명확합니다. **주요 콘텐츠와 사진은 배포본에 고정하고, 일정·지원/결과 설정·지원 링크는 접속할 때 Google Sheet에서 최신값을 읽습니다.**

운영진은 평소에 Codespace를 열지 않습니다. Google Sheets/Drive를 수정한 뒤 시트 메뉴의 **홈페이지 관리 → 변경사항 사이트에 반영**을 누릅니다.

## 실제 운영 흐름

1. Google Sheets에서 문구, 조직도, 소모임, 이벤트, 이미지 URL을 수정합니다.
2. 새 사진은 Google Drive 또는 외부 이미지 저장소에 올리고 공개 공유 링크를 시트에 붙입니다.
3. **홈페이지 관리 → 변경사항 사이트에 반영**을 누릅니다.
4. GitHub Actions가 시트 내용과 사진을 가져와 정적 파일로 커밋하고 사이트를 다시 배포합니다.
5. 보통 1~2분 뒤 배포된 주요 콘텐츠와 사진이 바뀝니다.

`Schedule`, `settings`, `recruitment` 탭의 지원 운영값은 예외입니다. 일정, 지원/결과 공개 기간, 지원 폼 링크·기간·버튼은 페이지를 열 때 직접 조회하므로 재배포 버튼을 누르지 않아도 됩니다. 지원자 결과는 `Applies`를 결과 조회 API가 요청 시 읽습니다.

## 연결 방식

브라우저는 배포된 `data/site-content.json`에서 주요 콘텐츠를 읽습니다. 배포 작업은 `tools/sheets-to-content.mjs`로 시트 탭을 읽고 JSON을 생성하며, 외부/Drive 사진은 `images/cms/` 아래 정적 파일로 내려받습니다. 사진 파일명에는 내용 해시가 들어가므로 같은 Drive 파일을 교체해도 새 배포에서 캐시가 자동 갱신됩니다.

브라우저가 Google Sheet를 직접 읽는 경로는 `Schedule`, `settings`, `recruitment`의 지원 운영값입니다. 조회가 실패하면 배포 JSON의 값이 안전한 대체값으로 남습니다. 개인정보가 있는 `Applies`는 브라우저에 공개하지 않고 결과 조회 API를 통해서만 한 명씩 조회합니다.

## 추천 방식

Google Sheet의 Apps Script에 `google-apps-script/content-api.gs`를 넣어 시트 메뉴와 GitHub 배포 버튼을 연결합니다.

권장 이름:

```text
PAINS_SITE_CMS
```

권장 Drive 폴더:

```text
PAINS_SITE_ASSETS
```

처음 세팅:

1. Google Drive에서 새 Google Sheet를 만듭니다.
2. 시트 이름을 `PAINS_SITE_CMS`로 바꿉니다.
3. 메뉴에서 `확장 프로그램 > Apps Script`를 엽니다.
4. `google-apps-script/content-api.gs` 전체 내용을 붙여넣고 저장합니다.
5. 기존 운영 시트라면 `upgradeSheetV2()`를 한 번 실행합니다. 새 시트만 `setupPainsCms()`를 실행합니다.
6. `setGithubSyncToken()`을 실행하고 `kupains/homepage` 저장소의 Contents 쓰기 권한이 있는 fine-grained token을 저장합니다.
7. 시트를 새로 열어 **홈페이지 관리 → 변경사항 사이트에 반영** 메뉴가 나타나는지 확인합니다.

이후부터는 Google Sheets/Drive를 수정하고 이 메뉴만 누르면 됩니다. 콘텐츠 동기화에 Apps Script 웹 앱 재배포나 Vercel 환경변수는 필요하지 않습니다.

이미 세팅된 뒤에는 `setupPainsCms`를 다시 실행하지 마세요. 다시 실행하면 현재 시트 내용이 초기 템플릿으로 덮입니다.

이미 쓰고 있는 시트를 최신 구조로 올릴 때는 `upgradeSheetV2`를 실행합니다. 입력해둔 값은 그대로 두고 구조만 정리하며, 실행 직전 상태는 `_backup_*` 탭으로 자동 저장됩니다.

## Drive 이미지 운영

이미지는 Google Drive에 올린 뒤 “링크가 있는 모든 사용자 보기 가능”으로 설정합니다.

시트에는 아래 둘 중 아무거나 넣어도 됩니다.

```text
https://drive.google.com/file/d/FILE_ID/view?usp=sharing
```

```text
https://drive.google.com/uc?export=view&id=FILE_ID
```

배포 작업이 Drive 공유 링크의 사진을 다운로드하고 `images/cms/`의 정적 파일 주소로 바꿉니다. Drive 파일은 반드시 “링크가 있는 모든 사용자 보기 가능”이어야 합니다. 다운로드에 실패하면 잘못된 사진으로 배포하지 않도록 GitHub Actions가 실패하고 기존 사이트는 유지됩니다.

## 아카이브 PDF 운영

프로젝트와 공지 PDF는 GitHub Release 대신 기존 `PAINS_SITE_CMS` Google Sheet와 Google Drive에서 함께 운영할 수 있습니다.

권장 흐름:

1. Google Drive에 프로젝트/공지 PDF를 올립니다.
2. 파일 공유를 `링크가 있는 모든 사용자 보기 가능`으로 바꿉니다.
3. 기존 CMS Google Sheet에 `projects`, `notices` 탭을 추가하고 메타데이터와 Drive 링크를 입력합니다.
4. 기존 `google-apps-script/content-api.gs`를 Apps Script에 다시 붙여넣고 새 버전으로 배포합니다.
5. `settings.projectArchiveApiUrl`, `settings.noticeArchiveApiUrl`은 비워둡니다. 비어 있으면 `/api/content.js` 안의 데이터를 바로 사용합니다.

`projects` 탭 권장 컬럼:

| title | year | generation | period | sport | driveUrl | driveId | fileName | visible | order |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 야구 특화 LLM: PA-LLMa | 2026 | 10기 | 방학 중 프로젝트 | 야구 | Drive 공유 링크 |  | 10V_10.pdf | TRUE | 1 |

`notices` 탭 권장 컬럼:

| title | date | generation | department | driveUrl | driveId | fileName | important | visible | order |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 고려대학교 스포츠 통계 동아리 PAINS 회칙 | 2026-03-16 | 11기 | 운영위원회 | Drive 공유 링크 |  | Laws_20260316.pdf | TRUE | TRUE | 1 |

`driveUrl`에는 아래 형식의 공유 링크를 넣으면 됩니다.

```text
https://drive.google.com/file/d/FILE_ID/view?usp=sharing
```

`driveId`만 넣어도 됩니다. 둘 다 있으면 `driveId`를 우선 사용합니다.

기존 GitHub Release 아카이브를 임시 fallback으로 유지하고 싶으면 `settings.projectArchiveApiUrl`이나 `settings.noticeArchiveApiUrl`에 별도 아카이브 API URL을 넣어둘 수 있습니다.

- 항상 열기: `applyEnabled` 또는 `resultEnabled`를 `TRUE`

- 일정으로 자동 관리: `AUTO`로 두고 `StartAt`, `EndAt` 수정
- 날짜 형식: `YYYY-MM-DD HH:mm`, 한국시간 기준

`home_schedule`

홈의 **다가오는 일정**은 오늘(한국시간) 이후 일정 가운데 날짜가 빠른 4개를 표시합니다. 지난 일정은 자동으로 제외되고, 표시할 일정이 4개보다 적으면 남은 칸에는 가장 일반적인 미정 표기인 `TBD`가 들어갑니다.

| date | title | tag | dateLabel | weekday | visible | order |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-09-05 | 정기 세미나 #1 | 정기 |  |  | TRUE | 1 |
| 2026-09-12 | 신입 부원 OT | 필수 행사 |  |  | TRUE | 2 |

- `date`: `YYYY-MM-DD` 형식의 행사일입니다. 오늘 일정도 포함됩니다.
- `title`: 가운데에 표시되는 행사명입니다.
- `tag`: 오른쪽 배지 문구입니다. `필수`, `정기`, `행사`, `필수 행사`처럼 원하는 표현을 직접 입력합니다.
- `dateLabel`, `weekday`: 날짜와 요일 표기를 직접 지정할 때만 사용하며, 비워두면 `MM.DD`와 영문 요일이 자동 생성됩니다.

## 코드가 필요한 경우

- 레이아웃 변경
- 애니메이션 변경
- 새 페이지/새 섹션 추가
- 카드 디자인 변경

문구, 사진, 순서, 노출 여부 변경에는 코드가 필요 없습니다.
